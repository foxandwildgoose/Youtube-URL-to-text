# Real GoPro recording validation

A representative 1 GB / 40-minute GoPro recording was not available during implementation. Small fixtures and mocks do not establish large-file readiness. Complete this test on the intended desktop/browser before relying on long recordings.

1. Configure `OPENAI_API_KEY`, `OPENAI_TRANSCRIPTION_MODEL=gpt-transcribe`, and a random 24+ character `TRANSCRIPTION_ACCESS_TOKEN` on the server. Set an API spending budget. This is an explicitly initiated paid integration test, unlike `npm test`.
2. Use a recent desktop Chromium browser with enough free memory/storage. Open developer tools → Network and the browser task manager before starting; record browser version, OS, available RAM, recording codec, resolution, byte size, and duration.
3. Drop one real ~1 GB, ~40-minute GoPro MP4 in **Upload File**. Confirm file name, size, duration, and local playback. No complete-file upload should appear in Network. Verify selection does not freeze the UI and YouTube mode still works.
4. Choose **Korean + English**, **AI Conference**, relevant names/technical terms, and your personal access code. Choose **Start transcription** and keep the tab active. Verify stage changes correspond to actual operations, and the theme/controls remain responsive.
5. Confirm local FFmpeg core/worker loading and audio extraction. Observe memory: there should be no deliberate 1 GB JavaScript `arrayBuffer()` read of the source. Record peak browser/worker memory and preprocessing time. Confirm failure guidance is usable if memory is insufficient.
6. Inspect transcription requests: only compressed audio, at most 3 MB audio per request and 3.5 MB total multipart body. No video frames or original MP4. Confirm requests are sequential. Inspect the exported backup's chunk plan for silence-aware core boundaries, clamped first/last bounds, and overlap on all adjacent chunks.
7. After several sections finish, select **Cancel**. Export a backup. Confirm completed raw transcripts/checkpoints remain. Reload, reopen the unfinished job, and select a different file: it should reject the mismatch. Re-select the original file and resume; completed sections must not trigger new paid requests.
8. Finish transcription. Immediately see one transcript without waiting for a summary. Check Korean/English switching and conventional spellings of Blackwell, Rubin, HBM4, NVLink, and any terms actually spoken.
9. Listen around every boundary (e.g. approximately 05:00, 10:00, 15:00), using saved chunk core times. Compare the audio ±15 seconds with merged text. Check for missing words or sentences; review every uncertain match. Check for duplicated boundary paragraphs, while ensuring intentional repetition elsewhere survives. Inspect raw checkpoint text and merge audits in the JSON backup if needed.
10. Seek via transcript timestamps. Confirm the UI labels estimated timing rather than implying word accuracy. Edit text and speaker labels, search the corrected text, reload, and verify edits persisted. Original raw checkpoint text must remain intact.
11. Export TXT (with/without BOM), SRT, VTT, Markdown, JSON, CSV, and Print / Save as PDF. Confirm UTF-8 Hangul, corrected text, selected summary/speaker/timestamp options, valid subtitle cues, and no API secrets or fake YouTube identifiers.
12. Rename/reopen/search the job. Export a backup, import it into a separate browser profile, and verify text, edits, summaries, settings, and checkpoints. Original media must not be included; re-select it for playback/resume.
13. Record costs, total runtime, peak memory, observed errors, boundary-quality notes, and pass/fail for each step. Repeat with a noisy conference sample and a mobile layout check. Do not label the 1 GB target validated until the real recording completes and its boundaries are reviewed.
